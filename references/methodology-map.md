# Карта методологии и маршрутизатор

## Четыре слоя проекта

1. **Смыслообразование:** Cynefin — домен задачи (clear/complicated/complex/chaotic) и честные выходы.
2. **Поиск правильной задачи:** границы, функция, потоки, CECA, Kepner-Tregoe, SSM/CATWOE, Double Diamond, тримминг, S-кривая.
3. **Решение задачи:** противоречия, принципы, разделение ФП, Su-Field/76 SIS, FOS/эффекты/биомимикрия, TOC Evaporating Cloud, OTSM, C-K, морфологический анализ, Axiomatic Design, SIT, синектика, латеральное мышление, ARIZ-85C.
4. **Обоснование концепции:** Decision Analysis (NASA/Pugh/Taguchi), DOE, STPA, реализуемость, риски, стоимость, доказательства, эксперимент.

## Быстрый выбор инструмента

| Наблюдение | Природа/модель | Инструмент |
|---|---|---|
| Причинность очевидна, есть стандарт | Clear | применяй стандарт, не изобретай |
| Улучшение одного ухудшает другое | Техническое противоречие | изобретательские принципы, матрица как подсказка |
| Свойство требуется и не требуется по условиям | Физическое противоречие | принципы разделения + эффекты/FOS |
| Два желания/ценности конфликтуют, компромисс неприемлем | Ложная дилемма | TOC Evaporating Cloud (вскрытие допущений) |
| Множество связанных недостатков/противоречий | Сеть проблем | OTSM Network of Problems |
| Не хватает знания для формулировки противоречия | Неопределённость | C-K theory / «сначала измерить» |
| Нужен систематический перебор конфигураций | Многомерная неформализуемая задача | морфологический анализ + CCA |
| Требования связаны (один параметр тянет другой) | Coupled design | Axiomatic Design → переведи в противоречие |
| Нет нужного взаимодействия | Неполный/недостаточный Su-Field | 76 SIS, класс 1/2 |
| Взаимодействие вредно | Вредный Su-Field | 76 SIS, разрушение/изоляция/изменение поля |
| Компонент дорог или избыточен | Функциональная модель | тримминг и перенос функции |
| Неизвестно, чем выполнить функцию | Обобщённая функция | FOS, научные эффекты, биомимикрия |
| Нужны идеи в границах системы | Инерция мышления | SIT (closed world), синектика, латеральное мышление |
| Несколько концепций, несколько критериев | Многокритериальный выбор | Decision Analysis (NASA/Pugh) |
| Решение должно быть устойчиво к шуму | Robust design | Taguchi (control vs noise) |
| Неясно, куда развивается система | Эволюционная модель | S-кривая и TESE |
| Простые инструменты не сняли ключевой конфликт | Мини-задача | ARIZ-85C (полный алгоритм) |
| Проблема «мягкая», цели и границы спорны | Социальная/организационная ситуация | SSM/CATWOE |
| Внезапное отклонение с неизвестной причиной | Отклонение | Kepner-Tregoe Problem Analysis (is/is-not) |
| Проблема нечёткая, нужен процесс | Неопределённый вызов | Double Diamond |

## Правило минимальной достаточности

Не загружай все справочники. Используй минимальный набор, который соответствует домену (Cynefin) и природе задачи. Для сложных и критичных задач допускается несколько независимых маршрутов с последующим сравнением. Каждый внешний метод — модуль с маркировкой `canonical`/`adaptation`/`heuristic`; метод не заменяет первоисточник и не отменяет проверку.
