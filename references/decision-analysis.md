# Decision Analysis — выбор и обоснование концепции

> Статус: **canonical**. Источники: NASA SE Handbook §6.8 Decision Analysis (https://www.nasa.gov/reference/6-0-crosscutting-technical-management/), Pugh matrix (https://en.wikipedia.org/wiki/Decision-matrix_method), Taguchi robust design (https://sixsigmastudyguide.com/taguchi-robust-design)

Применяй для количественного выбора между концепциями, когда критериев несколько и они конфликтуют. Дополняет качественную оценку из `evaluation.md`.

## Процедура (NASA §6.8)

1. **Определи решение** в контексте системы: нужный исход по performance, cost, schedule.
2. **Задай критерии**: обязательные (mandatory «shall have») и усиливающие (enhancing). Обязательные — отсечные: вариант без обязательного критерия отбрасывается до ранжирования.
3. **Собери альтернативы**, покрывающие пространство решения; используй trade tree для отсева вариантов.
4. **Выбери метод оценки**: симуляция, взвешенная матрица, trade study, HITL-тест, прототип.
5. **Нормализуй** разные шкалы критериев с **операциональными определениями** (что именно значит «высокий» — напр. «вероятность ≥ 67%»).
6. **Оцени устойчивость ранжирования** к неопределённости: если снижение неопределённости может изменить порядок — снижай её или рекомендую несколько близких вариантов.

## Pugh matrix (быстрый отсев)

- Выбери datum (базовый вариант), сравнивай каждый вариант по каждому критерию: лучше (+), хуже (−), равно (0).
- Критерии бери из спецификации продукта (PDS). При разной важности — взвешенный вариант.
- Суммируй, выяви лидеров и гибриды (комбинации сильных сторон).

## Taguchi robust design (устойчивость к шуму)

- Раздели факторы на **control** (задаёшь ты) и **noise** (варьируются в реальности).
- Варьируй noise намеренно, чтобы найти настройки control, устойчивые к нему (S/N-отношение).
- Применяй, когда решение должно быть нечувствительным к внешним/неконтролируемым факторам.

## Некомпенсируемые ограничения (обязательно)

Безопасность, право, жёсткие технические пределы — **отсечные** условия до ранжирования, а не компенсируемые баллы. Взвешенная сумма не должна «прощать» нарушение обязательного критерия.

## Ограничения применимости

- Веса и шкалы задаёт проект, а не навык; они должны иметь операциональные определения.
- Согласованные веса не устраняют неопределённость прогнозов по каждому критерию.
- Матрица — обоснование, а не доказательство: итоговое решение принимает ответственный.

## Проверка

- [ ] обязательные и усиливающие критерии разделены;
- [ ] каждая шкала имеет операциональное определение;
- [ ] устойчивость ранжирования к неопределённости оценена;
- [ ] нарушение обязательного критерия отсекает вариант, а не снижает балл.
