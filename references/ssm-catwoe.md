# SSM / CATWOE — «мягкие» организационные задачи

> Статус: **canonical**. Источник: Peter Checkland. Первоисточник: https://en.wikipedia.org/wiki/Soft_systems_methodology

Soft Systems Methodology (SSM) — способ мышления о проблемных социальных/организационных ситуациях, где нет одного «правильного» технического противоречия, а есть разные мировоззрения. Применяй, когда проблема «мягкая»: цели и границы спорны, участники расходятся в интересах.

## Ядро — root definition

Опиши систему как **процесс преобразования** (Transformation): вход → выход. Полная root definition задаётся мнемоникой **CATWOE**:

| Элемент | Вопрос |
|---|---|
| **C** — Customers | кто жертва/бенефициар преобразования |
| **A** — Actors | кто выполняет преобразование |
| **T** — Transformation | что во что преобразуется |
| **W** — Weltanschauung | мировоззрение, делающее T осмысленным |
| **O** — Owners | кто может остановить T |
| **E** — Environmental constraints | внешние ограничения, принимаемые как данность |

## Процедура (упрощённо)

1. Опиши проблемную ситуацию (rich picture) — участники, связи, конфликты.
2. Сформулируй несколько root definitions (по одному на значимое мировоззрение W).
3. Построй концептуальные модели деятельности для каждого.
4. Сравни модели с реальностью, найди расхождения.
5. Определи изменения: системно желаемые и культурно осуществимые.
6. Действуй и проверяй.

## Связь с ТРИЗ

SSM применяй, когда ещё нет чёткого противоречия, но есть конфликт интересов/мировоззрений. После root definition часто вскрывается ТП/ФП или дилемма → передай в ТРИЗ или TOC Evaporating Cloud.

## Ограничения применимости

- Не даёт «оптимального» решения — даёт структурированное понимание и перечень изменений.
- Мировоззрение W должно быть явным: без него root definition неоднозначен.

## Проверка

- [ ] Transformation описан как преобразование, а не как цель;
- [ ] CATWOE заполнено полностью;
- [ ] рассмотрено более одного мировоззрения;
- [ ] изменения разделены на желаемые и осуществимые.
