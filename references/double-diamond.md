# Double Diamond — рамка процесса для нечёткой задачи

> Статус: **canonical**. Источник: UK Design Council. Первоисточник: https://www.designcouncil.org.uk/resources/framework-for-innovation/

Double Diamond — визуальная модель процесса дизайна: два «ромба» расхождения (divergent) и схождения (convergent). Применяй как **входную рамку**, когда проблема нечёткая и нужно сначала понять её, прежде чем решать.

## Четыре фазы

1. **Discover** (расхождение) — пойми проблему, а не предполагай; говори с теми, кого она касается.
2. **Define** (схождение) — переформулируй вызов на основе инсайтов.
3. **Develop** (расхождение) — дай разные ответы на чётко определённую проблему, ищи вдохновение, со-создавай.
4. **Deliver** (схождение) — проверяй решения в малом масштабе, отбрасывай нерабочие, улучшай рабочие.

Процесс нелинейный: тесты ранних идей могут быть частью Discover.

## Четыре принципа

1. **Люди прежде всего** — начинай с потребностей и устремлений пользователей.
2. **Общайся наглядно и инклюзивно** — общее понимание через визуализацию.
3. **Сотрудничай и со-создавай** — вдохновляйся чужими подходами.
4. **Итерируй** — раннее выявление ошибок, снижение риска.

## Связь с ТРИЗ

Double Diamond — **процесс**, ТРИЗ — **метод** внутри фаз: Define → формулировка ключевой задачи/противоречия; Develop → генераторы (SIT/синектика/C-K); Deliver → обоснование и проверка (decision-analysis/doe).

## Ограничения применимости

- Не даёт инструментов анализа/генерации — только фазы и принципы.
- Для чёткой технической задачи избыточен; используй ТРИЗ-маршрут напрямую.

## Проверка

- [ ] фаза Discover выполнена до формулировки решения;
- [ ] вызов переформулирован на этапе Define;
- [ ] решения проверены в малом масштабе (Deliver), а не утверждены сразу.
