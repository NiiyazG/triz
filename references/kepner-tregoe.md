# Kepner-Tregoe — структурная диагностика и решение

> Статус: **canonical**. Источник: Charles Kepner, Benjamin Tregoe. Первоисточник: https://purplegriffon.com/blog/kepner-tregoe-method

Kepner-Tregoe (KT) — четыре взаимодополняющих процесса для структурной работы с проблемами и решениями. Применяй для ранжирования проблем, поиска причины и обоснованного выбора, когда нужен строгий порядок до ТРИЗ.

## Четыре процесса

### 1. Situation Appraisal (оценка ситуации)

Перечисли проблемы/задачи, ранжируй по серьёзности, срочности и тенденции роста; распредели, какой процесс применить к каждой (анализ проблемы / решение / потенциальная проблема).

### 2. Problem Analysis (анализ проблемы)

- Опиши отклонение: «что есть» vs «что должно быть».
- Задай **is / is-not** по четырём измерениям: что, где, когда, масштаб.
- Сравни «есть» и «нет», найди **различие** — оно указывает на причину.
- Проверь гипотезу причины: объясняет ли она все факты.

### 3. Decision Analysis (анализ решения)

- Задай **обязательные (musts)** и **желательные (wants)** критерии.
- Отсеки варианты по musts; оцени оставшиеся по wants с весами.
- Оцени риски каждого варианта (adverse consequences) и выбери.

### 4. Potential Problem Analysis (анализ потенциальных проблем)

- Для выбранного действия перечисли возможные сбои, их причины, меры предотвращения и план реагирования.

## Связь с ТРИЗ

Problem Analysis (is/is-not) даёт проверяемую причину — вход в CECA/противоречие. Decision Analysis — быстрая альтернатива `decision-analysis.md`. Potential Problem Analysis ≈ диверсионная проверка ТРИЗ.

## Ограничения применимости

- is/is-not силён для внезапных отклонений, слабее для эмерджентных/комплексных проблем.
- Веса и musts задаёт контекст, а не навык.

## Проверка

- [ ] отклонение описано как «есть vs должно быть»;
- [ ] is/is-not заполнено по всем четырём измерениям;
- [ ] причина объясняет все факты, а не часть;
- [ ] musts отделены от wants.
